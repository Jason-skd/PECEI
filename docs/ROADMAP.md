## 0. 一句话定位

我们在一个**网格世界后端**上，构建一个具身智能体，让它对**自己生成的造物**跑一条**分化—进化—再生**的闭环。造物同时包含**躯体(body)**与**心智(mind)**：世界被刻意设计成"智能体本体够不到目标"的形态，迫使它**造出一个助手、为它写大脑、再与它协作**；当环境打破造物的假设时，智能体**先诊断、再定点重写躯体或心智**，并跨一次次尝试积累可复用的经验与原则。

由于缺乏真实机器人硬件与 world model 的算力，网格世界是我们对真实具身场景的**有原则的等效替代(principled surrogate)**；其抽象层与真实机器人的 primitive 层同构，因此整套架构是一个**可迁移的 prototype**。

> 设计框架借鉴发育生物学的"分化—进化—繁殖"时间尺度分层，但所有机制均以 **LLM 符号化方式**实现（不依赖梯度训练）。文中生物学措辞均为 **inspired-by 的类比实现，非生物学保真**——这是与"网格世界作为 surrogate"同源的诚实边界。

## 1. 核心命题 (Thesis)

> **Mind and Body, Both Authored.**
> 一个具身智能体不仅生成、而且要**再生**它的造物；造物同时包含**躯体**(由材料合成的物理形态)与**心智**(智能体为造物编写的控制程序)。环境既**物理地强制**智能体依赖造物(本体进不去)，又**动态地强制**它在失败后重造/重写。智能体对造物的整套操作构成一条**分化—进化—再生**闭环。

**两个动词的精确定义：**

- **Generate(= 分化)**：在某个决策点，智能体由通用 LLM 基座"分化"出为当前任务定制的造物，合成两份 artifact——
  - **Body**：一份**类型化的材料规格**(材料组合 + 导出属性 + 物理约束)，随后在场景中由材料拼装而成。
  - **Mind**：一段**类型化的控制程序**(DSL)，驱动该造物行动。
- **Regenerate(= 定点再生)**：当任一 artifact 失效时，智能体**先诊断失效归因**(§4.4)，再**只重写出错的那一处**(fault-localized)，而非整体推倒重来。跨 episode 累积的反思、技能与原则，使每一次 regenerate 都比上一次更有依据。

## 2. 方法论总纲：网格世界为何"等同"于真实具身实验

这是整个方案必须先立住的逻辑，也是 mentor 最可能追问的地方。

**核心论点：** 智能体的"心智"(策略程序)与"躯体规格"被表达成一种**后端无关(binding-agnostic)**的形式。网格世界只是"世界模型 + 物理"的一个 **mock 后端**。把后端从 gridworld 换成真实机器人的 primitive API，**整个三层闭环的控制结构与记忆机制原样保留**。因此我们的贡献(架构 + 学习机制)是硬件无关的；网格世界只是"买不起机器、也跑不起 world model"时，仍能完整跑通这条闭环的**最廉价后端**。

**抽象层同构表(辩护词)：**

| 网格世界抽象                   | 真实具身对应                        | 为何可迁移                                   |
| ------------------------------ | ----------------------------------- | -------------------------------------------- |
| 离散网格 + 单元占用            | 占用栅格 (occupancy grid)           | 本就是真实机器人导航的真实表示               |
| 动作 DSL(`move`/`turn`/`pick`) | 运动原语 (motion primitives)        | 真实控制栈即如此分层                         |
| 材料 + 属性(防火/防水/浮力)    | 物体的 affordance / 材料属性        | 同一套符号推理                               |
| 由材料拼装的造物               | 机器人**制造/部署的工具或子智能体** | 真实 tool-use / 可部署子体                   |
| 心智 = 控制程序                | 可执行的机器人控制程序              | **1:1**，同一程序换底层 binding 即可驱动机器 |
| body-spec 再生(外循环)         | 形态自我再设计 / 硬件繁殖           | 控制结构完全相同，仅替换物理实现             |

**诚实的边界(主动划清，反而更可信)：**
网格世界**不**模拟连续动力学、摩擦、感知噪声、真实制造。因此本 prototype 验证的是**决策/控制层的迁移**，而非物理保真度。物理保真度正是 world model 该补的洞——**而这恰好就是我们买不起的东西**。动机与方法的缺口在此闭环。

## 3. 三层闭环架构（系统骨架）

系统由三个嵌套闭环组成，分别运行在不同时间尺度上，对应生物学的"生理调节—个体发育—物种进化"，在本项目中等价为"**单步执行—跨次进化—形态再生**"。三层相互供能，构成能力螺旋上升的正反馈。

```
                        ┌─────────────────────────────────────────────┐
                        │            后端：Gymnasium + MiniGrid          │
                        │   救援网格世界（占用栅格 + 材料 + 危险 + 幸存者）│
                        │   ★ forced-dependency 关卡：本体进不去        │
                        └──────────────────────┬──────────────────────┘
                                               │ 结构化 observation
        ┌──────────────────────────────────────┼──────────────────────────────────────┐
        │                                      ▼                                      │
        │  ┌──────────────────── 内循环（单步 / 单 episode）────────────────────┐     │
        │  │  LLM 生成 Body(spec)+ Mind(DSL) → 静态检查 → 沙盒执行 → 记录轨迹   │     │
        │  │  失败 → 诊断(mind or body?) → 定点 regenerate                      │     │
        │  └──────────────────────────────┬──────────────────────────────────┘     │
        │                                 │ 经验沉淀                                 │
        │                                 ▼                                          │
        │  ┌──────────────────── 中循环（跨 episode）──────────────────────────┐   │
   前端 │  │  反思(Reflexion) + 技能原子(经验原子)累积与组合复用                  │   │
  (LLM) │  │  跨生成的 creature 共享记忆（拉马克式即时继承）                      │   │
        │  │  离线蒸馏 → 优化原则 / 学习禁忌（元认知层，注入 prompt 当先验）      │   │
        │  └──────────────────────────────┬──────────────────────────────────┘   │
        │                                 │ 持续性 body 瓶颈信号                    │
        │                                 ▼                                          │
        │  ┌──────────────────── 外循环（形态再生）────────────────────────────┐  │
        │  │  自我诊断：mind 反复失败且归因到 body → 生成新 body-spec(蓝图)      │  │
        │  │  → 静态校验 → 场景内由材料拼装(制造的 surrogate) → 新形态开启新轮   │  │
        │  └──────────────────────────────────────────────────────────────────┘  │
        └──────────────────────────────────────────────────────────────────────────┘
```

**三层耦合：** 内循环为中循环供料(经验)；中循环为内循环赋能(先验 + 可复用技能)；中循环的"持续性 body 瓶颈"触发外循环；外循环的新形态改变内循环的感知—行动边界，开启新一轮更高水平的分化。

**海报视觉隐喻：** LLM = **数字胚胎干细胞**(通用、未特化、保有分化潜能)；每个被生成的 creature = 一条**分化谱系**；技能库 = **共享记忆**；body 再生 = **形态进化**。

## 4. 内循环：Generate / Regenerate（单 episode 内）

控制模式：**program-ahead + 感知 + 失败重入**（非逐帧 reactive——后者与"AI 写控制代码"主题冲突）。LLM 写一段程序或一份造物规格，沙盒自主执行多步，只在结束/失败/主动 yield 时把控制权交还。

### 4.1 两份生成的 artifact

| artifact       | 形态                                                              | 校验时机                                                    | 失效含义                                 |
| -------------- | ----------------------------------------------------------------- | ----------------------------------------------------------- | ---------------------------------------- |
| **Body(躯体)** | 类型化材料规格：`{材料集合, 导出属性(防火/小型/浮力…), 物理约束}` | **编译期**：静态 checker 校验材料兼容性、属性推导、约束满足 | 规格自相矛盾(如"防火但用了易燃材料")     |
| **Mind(心智)** | 类型化 DSL 控制程序                                               | **编译期**：类型/语法/schema 校验；**运行期**：在世界中执行 | 程序逻辑错(撞墙、卡死、超时、造物被烧毁) |

> body 与 mind **对称**：两者都是生成的 artifact，都可能是 regenerate 的对象。这一对称天然适配 PL/AI4SE 工具链，也使"先诊断、再定点再生"成为可能。

### 4.2 失败分层

- **编译期失败(compile-time)**：body-spec 或程序通不过静态检查 → 在**生成阶段**即挡掉。
  - 实现手段：API 路线用 **tool-use / JSON schema 约束输出**(让 LLM 吐符合 schema 的 AST，schema 合法即可解析、基础类型合法)；本地路线可进一步做 **type-directed decoding**(逐 token mask)。
- **运行期失败(runtime)**：通过了静态检查，但在世界中执行失败 → 走**故障定位再生**。

### 4.3 故障定位再生(fault-localized regeneration)

运行期失败不整体重写，而是：
1. 从**执行轨迹尾部**定位出错的程序节点 / 造物部位；
2. 只让 LLM **regenerate 那一处**(self-repair / backtracking debug 范式)；
3. 重新部署，直到成功或耗尽预算。

这是 generate/regenerate 最有说服力的演示形态：**"先编译期拦截，再运行期定位修复"**，直接复用团队在 PL/AI4SE 方向的积累。

### 4.4 自我诊断：regenerate body 还是 mind（核心决策规则）

失败后并非无脑全改，而是**先归因**：

| 失败特征（在网格世界中可观测）                                | 归因          | 动作                                 |
| ------------------------------------------------------------- | ------------- | ------------------------------------ |
| 撞墙、命令不合法、循环、超时、轨迹逻辑错                      | **mind 失败** | fault-localized 重写程序节点         |
| 物理被挡（体型进不去）、被环境属性击败（烧毁/淹没）、抗性不足 | **body 失败** | 触发**外循环**，regenerate body-spec |

这一规则把"regenerate 哪个 artifact"从一个开放问题变成**有诊断信号支撑的机制决策**，也是内循环与外循环的接口。

### 4.5 强制依赖关卡(forced-dependency level)

至少一个关卡，把"必须依赖造物"做成**硬性的关卡规则**：
- agent 本体被物理挡住（体型下限使它进不了 1 格窄洞 / 本体不防火无法穿过火区）；
- 唯一解：造一个**体型更小 / 防火**的助手，为它写 mind，再与之协作把幸存者救出。

这使主题"可见、可演示、可量化"。

## 5. 中循环：Verbal RL 与"进化"（跨 episode）

用 LLM API 即意味着**无法做梯度学习**。"学习/积累经验"由 prompt/harness 层的记忆机制实现。中循环把跨 episode 的经验组织成三条逐层升高的机制——它们正是生物学"进化"在我们这套里的符号化实现。

### 5.1 结构红利：记忆—推理分离（免费获得，无需备份机制）

梯度范式为避免灾难性遗忘需要"临时备份"等额外机制；而在本系统中，**LLM 推理是无状态的，所有经验都在外部 store——记忆与推理在结构上本就分离，灾难性遗忘在机制上不可能发生。** 我们因此**免费**获得"大胆探索不污染持久能力"的性质，无需备份机制。这是用 LLM-agent 范式替代梯度范式时自然获得的结构优势。

### 5.2 反思(Reflexion) + 技能原子(经验原子)

- **Reflexion(文字反思)**：每次失败后，LLM 写一段反思(哪里错、下次怎么改)，存入记忆库；后续检索 top-k 塞入 prompt。零梯度，跨 episode 提升。
- **技能原子(经验原子)**：成功的 mind-程序被拆解为可复用的最小片段，每片携带三类元数据——`{前置条件(何种情境成立), 操作内容(DSL 代码片段), 效果度量(可量化结果)}`。面对新任务时，检索相似情境的原子并**排列组合**成候选程序。这把技能库从"档案柜"升级为**可组合的知识基底**。

> 注：在梯度语境下"经验原子"被构想为参数调整向量（跨架构聚类在技术上欠定）；在我们这里它落地为**程序片段**——更具体、可解析、可验证。

### 5.3 共享记忆 / 拉马克式即时继承

同一 agent 跨**它自己生成的多个 creature** 共享同一个技能库与反思库：一个 creature 学到的技巧，**即时**被下一个 creature 继承。多 creature 协作时，这就是字面意义的群体学习。群体规模增长带来"越用越强"的正反馈，而非重复学习的线性成本。

### 5.4 优化原则 / 学习禁忌（元认知层，在 Reflexion 之上）

周期性地对记忆库中的反思与失败类型做**离线聚类**，蒸馏出少量跨任务通用的**优化原则**与**学习禁忌**（如"窄洞卡住时，改 body 比改 mind 成功率高 80%"），作为持久先验注入 prompt。这一层把系统从"经验学习者"提升为"元认知反思者"，使"进化"从口号变成可见机制。

> 实现成本：用 sentence-transformers 在 CPU 上做文本聚类，或直接让 LLM 自行聚类，**无需训练**。诚实边界：10 天能跑的 episode 数有限，这一层适合作为**机制演示**而非稳健统计结论。

### 5.5 上下文窗口（已解决的工程问题）

| 组成                                | 估算 tokens |
| ----------------------------------- | ----------- |
| 网格 observation（占用栅格 + 状态） | ~200–300    |
| mind 程序                           | ~100–800    |
| 失败轨迹尾部（k≈20 步）             | ~1,000      |
| Reflexion 反思 top-5                | ~750        |
| 技能签名                            | ~500        |
| **单次决策 prompt 合计**            | **~2–4k**   |

相对 Haiku 4.5 的 200k 上下文有 50–100 倍余量。只要用"检索 top-k + 反思摘要"而非全量拼接，上下文就不是技术障碍。

## 6. 外循环：形态再生（"繁殖"的 surrogate）

当 mind 反复 regenerate 仍停滞于平台期，且失败可归因到 body 的物理量（体型/抗性），系统判为**body 瓶颈**，触发外循环：在缺真实硬件/算力时，"硬件繁殖"等价为 **body-spec 的符号化再生**——保留逻辑，替换物理实现。

**三环节：**
1. **自我诊断**：区分"软件可弥补型失败"(改 mind 即可)与"硬件瓶颈型失败"(mind 多次改仍停滞、且可归因到 body 物理量)。诊断规则见 §4.4。
2. **蓝图生成**：在形态空间搜索新 body-spec（改材料 / 改属性 / 改尺寸），由静态 checker 校验。
3. **拼装(制造的 surrogate)**：在场景内由材料 bounded-constructive 拼装出新形态（= 真实模块化制造/增材制造的符号替代）。新 creature 继承中循环的全部共享记忆——"出厂即巅峰"。

**基座进化阶梯（"代际升级"在无梯度下的等价物）：**
- 免费档：进化的是 **prompt / 技能库 / 蒸馏原则**（持久先验随经验增长）。
- Gold 档：在本机 **MLX** 上做一次小 **LoRA**，把稳定原则固化进基座权重——这是字面意义上的"基座代际进化"。

## 7. 实验设计（产出海报证据）

在同一后端上对照不同"学习范式"，且**消解维度正好对应三层闭环是否开启**：

| 条件                              | 智能体                           | 启用的循环   | 学习来源            |
| --------------------------------- | -------------------------------- | ------------ | ------------------- |
| **(A) 小 RL baseline**            | <1M 参数小策略，PPO，PyTorch MPS | —            | 从 reward 学习      |
| **(B) 裸 LLM agent**              | LLM，无记忆                      | 仅内循环     | 仅当场推理          |
| **(C) LLM + 中循环**              | LLM + 反思 + 技能原子 + 原则     | 内 + 中      | 跨 episode 经验复用 |
| **(D) LLM + 中 + 外循环**（可选） | 再加 body-spec 再生              | 内 + 中 + 外 | 形态层面的再生      |

**为什么必须有 (A)：** 小 RL baseline 不是跑龙套，而是**论证的一部分**——"我们买不起 world model / 大 RL，所以用 gridworld + 小策略当 principled surrogate；而 verbal-RL 的 LLM agent 在同样廉价的后端上展现了另一种学习范式。"这让海报从"软件演示"升级为"有对照的实验"。

**指标：** 成功率、救人所耗步数、每 episode 的 regenerate 次数、各条件随 episode 的成功率曲线、mind-regen 与 body-regen 的触发比例。

**关键可视化：** 一张 **generate → 诊断 → regenerate → success** 的时间线图（海报杀手锏）；一张多条件成功率对比图。

## 8. 技术栈

| 层                   | 选型                                                          | 说明                                                                                                        |
| -------------------- | ------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| 环境 / mock 后端     | **Gymnasium + MiniGrid**                                      | 标准 RL API；MiniGrid 易改自定义地图；后端可替换                                                            |
| 智能体大脑（主线）   | **Claude API（Haiku 4.5）**                                   | 动作循环用便宜模型；网格世界步数少，成本极低；离线可缓存                                                    |
| 本地模型（可选加分） | **MLX / mlx-lm（不要用 Ollama）**                             | 苹果统一内存优化；7–8B Q4 在 24G 上舒适运行；原生支持 LoRA。用于 constrained-decoding 的 PL 演示或本地 LoRA |
| 小 RL baseline       | **PyTorch MPS 后端**                                          | M5 上跑 <1M 参数小策略，数小时级                                                                            |
| 结构化/类型安全输出  | **API：tool-use / JSON schema**；本地：type-directed decoding | 见 §4.2                                                                                                     |
| 原则蒸馏（Silver+）  | **sentence-transformers（CPU）或 LLM 自聚类**                 | 无需训练                                                                                                    |

**本地模型纠偏：** 团队机器为 M5 24G。**用 MLX 而非 Ollama**——7–8B 4-bit 模型运行舒适、几乎不 swap；12B Q4 可放；14B 会 OOM。Gold 档的 LoRA 可在本机用 mlx-lm 完成，无需 Colab。

## 12. 硬约束与待定决策

### 硬技术约束（不可商量）

1. **真·decode-time 类型安全需要 logit 访问** → 只能用本地模型(MLX)；API 仅能给 schema 级结构保证。
2. **任意 Python + exec 必崩** → 必须是 DSL（声明式或过程式皆可，但不能是自由 Python）。
3. **纯逐帧 reactive 与"AI 写控制代码"主题冲突** → 必须 program-ahead。
4. **LLM API 不可能梯度学习** → 学习只能靠反思/技能库/原则蒸馏等记忆机制。
5. **本地 14B 在 24G 上 OOM** → 本地上限约 12B 且慢；要稳就 MLX + 7–8B Q4。

### 已定决策（不再讨论）

- **三层闭环**为系统骨架；**body 作为 typed spec**；body-spec 为 **bounded-constructive 拼装**；**§4.4 自我诊断规则**；**小 RL baseline** 纳入实验；中循环用 **Reflexion + 技能原子 + 共享记忆**；基座进化走 **prompt 原则(免费)→ 可选 LoRA(Gold)** 阶梯。

### 待定决策（实现阶段定，留给小组）

- DSL 具体原语集（示例供讨论：`move(n); turn(dir); pick(material); craft(tool,[materials]); deploy(body); assemble_creature(name,body); command(name,program); scan(cell); rescue(id)`）。
- 地图难度、episode 数量、原则蒸馏的具体聚类方法。
- 是否上本地模型做 constrained-decoding 演示（Gold 可选）。
